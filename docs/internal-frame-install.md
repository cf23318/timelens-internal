# TimeLens Internal 本地构建与逐机配置

此版本保留默认中文、浅色、窗口边框、无OCR回放、手动开始和暂停取消。默认两个工作日×8小时，可在任务开始前配置每天小时数；默认前台所在屏幕，全部屏幕仍需单独选择。

## 安装

macOS用已审查的依赖运行`scripts/build-internal-macos.sh`。它只构建`.app`并输出源码指纹，不安装、不启动、不录屏、不上传、不授系统权限。构建产物位于`project/src-tauri/target/release/bundle/macos/`。未签名/未公证构建仍需按本机系统提示处理，脚本不关闭系统安全设置。

Windows沿用Tauri NSIS的当前用户安装模式。此模式是Tauri默认行为；本次没有Windows真机安装验收，不将Mac编译或接口检查当作Windows已验收。不要直接执行另一份交付源码的安装器或逐机脚本。

新启动保持暂停，权限由系统交互授予。不要覆盖上游个人版的数据目录；此版使用`~/.timelens-internal`，标识`com.timelens.internal`。本次没有安装到系统应用目录，也没有修改现有用户数据。

## 上传配置

在管理员配置页填写国内接收服务器的HTTPS根地址、独立调研编号和设备编号，核实目的地后保存。编号1–64字符，以英文字母或数字开始，仅包含字母、数字、点、下划线和横线。不填写age公钥。

token从`TIMELENS_UPLOAD_TOKEN`环境变量或当前用户`~/.timelens-internal/upload-token`读取，至少32个非空白ASCII字符；不通过聊天、命令参数或源码传递真实token。macOS/Linux文件必须0600、目录0700且由当前用户拥有，拒绝符号链接。Windows需在文件安全设置中移除继承权限，只授予当前用户所需读写，安装管理员应核对ACL。

保存配置不会上传。点击“确认并启用本次后台上传”，查看范围并勾选确认，才会发送新队列中的原始截图。后台上传可单独停止，正在途中的请求可能仍返回回执。重启上传默认关闭，需要重新确认；采集仍需手动开始。

仅发送原始WebP和必要的设备/调研、时间、显示器、大小、哈希信息；不上传活动数据库。成功和失败均保留本地图片与数据库，不进行30天自动删除。旧截图不自动加入新队列；已有旧age包/旧回执任务需人工核对，不自动转换、解密、上传或清理。

隐私过滤仅按最前面的应用名、标识、窗口标题和网址判断，并在截图前后及保存前重新核对前台状态。后台应用不阻止截图，露出的后台内容可能入镜，无像素打码；处理敏感内容时应暂停采集。真实双屏、混合DPI、权限撤回、断网恢复、TLS和OSS需用约定的测试数据逐项验收。

## 本地测试

`cargo test --manifest-path project/src-tauri/Cargo.toml --lib`运行Rust假数据测试；接收服务和跨语言合同测试见`upload-server/README.md`。测试目录使用临时生成的图片、独立数据库和内存OSS，不截图、不读取用户历史图、不使用真实OSS凭据。

## 交付包中的环境目标

服务端模板已保留交付包指定的北京 OSS 桶 `umall-video-record` 和内网端点；非阿里云内网环境使用北京公网端点。客户端示例地址 `https://upload.timelens.internal` 仅供管理员核对，尚未验证其实际部署和连通性。两个模板位于 `upload-server/deploy/`，不会自动修改当前用户配置或启用上传。

交付包只附占位的 AccessKey/token，未附可直接使用的完整凭据。若现有服务器运行对方原版服务，还需部署兼容本地新版的接收服务；本次没有执行任何线上改动。
