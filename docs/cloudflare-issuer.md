# Cloudflare自助登记、授权与自动续期

## 员工使用

安装软件并完成首次系统权限 → 首页填写姓名 → 点击“开始采集”。员工不导入JSON、不填写OSS地址、不处理Token。记录和自动同步状态可见，可随时暂停；退出/重启不会自动开始采集，已停止同步的选择会保留。

准入按用户明确要求：填写姓名即视为员工，不校验劳动关系、企业账号或真实姓名。持有安装包、源码或接口地址的外部人也可自助注册。姓名只作为填写信息，固定设备ID与首次生成的私有随机凭据绑定；后续凭据用于设备续期，不代表真实人员身份认证。删除或克隆本地profile会改变或复制设备身份。

安装包只含公开注册配置 `project/config/employee-registration.json`，不含批次激活码、包解密密钥或OSS长期Secret。首次点击开始时先保存姓名、随机设备私有凭据和固定的批准结束，再在后台调用 `/v1/register` 取得上传授权；之后自动调用 `/v1/renew`。首次离线也可记录，联网后用原身份和原截止重试。成功回复丢失不会重复占名额。

公开服务地址为 `https://timelens-oss-issuer.cf23318-hermes.workers.dev/`。Cloudflare接收首次填写的姓名以校验非空，不持久保存姓名、不记录请求正文；它保存随机设备ID、凭据哈希、批次、签发和截止台账。图片及清单由客户端直接上传北京OSS，姓名仍在OSS对象目录中。Cloudflare不接收截图或活动数据库。

## 时间、留存与限额

- 上传授权最长7天，运行中在到期前24小时检查续期。失败按退避重试；用户无需每7天领取配置。
- 每台新设备在本机首次准备时固定批准结束，默认加7天；这一值不会因注册重试、重启、升级或续期延长。服务器统一秒精度，最多容忍2分钟正时钟偏差。首次离线至任务结束仍可在原归属及留存期限内注册并补传。
- 开放批次可以长期接纳新设备；批次的准入上限不是设备的数据保留期限。签名、OSS元数据、回读台账、管理员同步全部使用各设备自己的批准结束。旧激活设备才回退使用原批次的固定截止。
- 累计采集目标仍为48小时，暂停和睡眠不累计。留存按实际/批准结束较早者加30天，已经签发的授权排空后清理。上传成功不立即删除原图。
- 服务单批次最多1000台、累计最多2000台、最多200个批次。本轮验收只开放既有 `cf-new-user-20261026` 测试批次，名额1台、首次登记截止由测试计划限定。正式多人准入的人数及开放时限需另行明确，未创建2099年/1000台的正式批次。容量耗尽会拒绝新注册，不影响原设备按原范围续期；扩容前须专项调整。姓名并不能阻止他人消耗名额。

## 服务部署

源码在 `cloudflare-issuer/`，Worker加SQLite Durable Object，状态串行化；正文限长限时读取，先持久记录签发到期再返回可用授权。关闭观测日志和遥测，响应禁用缓存，不允许请求跳转。

| 配置 | 位置 | 作用 |
|---|---|---|
| OSS_BUCKET、PUBLIC_ISSUER_URL | Worker变量 | 固定北京Bucket与签发根地址 |
| OPEN_REGISTRATION_BATCH | Worker变量 | 只允许新设备加入此固定device范围批次 |
| OPEN_REGISTRATION_WINDOW_DAYS | Worker变量，默认7，允许1–30 | 新设备批准结束的最大窗口 |
| OSS_ACCESS_KEY_ID、OSS_ACCESS_KEY_SECRET | Worker Secrets | 签发POST上传策略；客户端不取得长期Secret |
| ISSUER_ADMIN_TOKEN | Worker Secret | 管理批次和停用设备 |
| ISSUER_SYNC_TOKEN | Worker Secret | 同步台账和缩短删除屏障 |

真实账号、Secret和管理配置保存在源码外0600文件，部署通过Wrangler读取私有配置和Secret文件。OSS长期Secret不进入GitHub。生产变更需明确授权，不运行匿名反向猜测或提取他人凭据。

管理员一次建立长期开放的device范围批次后设置OPEN_REGISTRATION_BATCH。旧批次CLI继续保留，激活截止、名额、批准结束等字段仍严格且幂等；开放批次的远期批准结束只控制批次上限，新设备始终单独写入plannedEndMs和自身删除期限。不得通过清空Durable Object重置签发/截止台账。

| 接口 | 认证 | 说明 |
|---|---|---|
| GET /v1/config | 无 | 仅返回公开服务配置，无上传凭据 |
| POST /v1/register | 姓名、固定ID、本机私有随机凭据 | 开放自助登记；不能自选Bucket或任意前缀 |
| POST /v1/renew | 设备Bearer凭据 | 自动续期，只返回原范围；不得修改原截止 |
| POST /admin/batches | 管理Token | 创建不可变批次；成功响应丢失可原参数恢复 |
| POST /admin/device | 管理Token | 停用设备，已有授权仍可用至其到期 |
| POST /admin/sync | 管理或同步Token | 原子缩短删除上限并读取最大已签发到期 |
| POST /v1/activate | 旧激活码及设备凭据 | 兼容历史激活包和原公用授权 |

新登记在停止准入后会被拒绝。已有设备即使首次成功回复丢失，也可用原密钥、批次和原截止重试；不重新计数，不重置管理员已缩短的删除屏障。旧设备和shared授权兼容。409、CRC、回执异常不会被自动重置为成功或无限重试。

## 公开安装包与GitHub

普通PR、main和手动Build均可生成员工包：CI把仓库内公开注册配置复制到临时0600文件，经build.rs严格验证后编译。新增字段、重复字段、激活凭据或OSS长期Secret会被注册格式拒绝。缺少预置的release构建默认失败，管理员诊断包才显式允许空预置。

CI不使用真实Secrets或真实截图。实际standalone、Mac app/DMG或Windows NSIS内的程序必须核对安全检查协议、预置指纹、`employeeMode=true`、`bootstrapCredentialEmbedded=false`，再输出BUILD-INFO及SHA256SUMS。公开包不再需要加密分发，员工下载安装即可。旧激活格式仅供历史诊断；若管理员另行构建含真实激活码的旧包，仍必须内部发放，不能当作当前无凭据公开包。

本机手动构建也可把公开配置复制成0600临时文件，再通过 `TIMELENS_ACTIVATION_CONFIG` 指定；这个变量名称保留历史兼容，其内容可以是公开注册配置。现有build-internal脚本不自动安装、录屏或授系统权限。

## 管理员对账和清理

管理员工具与客户端应配套更新；姓名目录和每设备plannedEndMs必须由新版解析。管理员私有台账目录的 `cloud-issuer.json` 只含issuerUrl和syncToken，源码外的OSS管理员凭据仍只在管理员机器上。同步云端设备及最大签发到期 → 发现OSS任务/清单 → 原子缩短删除屏障 → 等待最大签发到期加120秒 → 执行到期删除。

缺少云端配置、网络失败、身份冲突或台账缺失时禁止云管理范围删除并报警。管理机仍须在线；迁移签发服务不会自动把原图回读和删除执行搬到Cloudflare。本机休眠时清理会延后，原本已批准的30天留存规则保持。

## 验证边界

Worker单元及本机workerd/SQLite重启覆盖旧激活、自助登记、重复和并发、每设备期限、秒精度/时钟偏差、设备冒领拒绝、名额和删除屏障。Rust回环TLS测试覆盖无激活码注册、离线失败与恢复、任务先结束、续期和范围不变；Python假Bucket验证台账、回读和删除。

GitHub构建成功与生产部署、真实Mac采集或Windows实机验收分别记录。包目前无组织Developer ID、公证或Windows代码签名；不得据此宣称正式签名发行。
